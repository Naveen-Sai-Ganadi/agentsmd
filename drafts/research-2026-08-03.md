# Research log — 2026-08-03

Five fresh signals confirming today's ship (`long-file` 200-line budget in `lint` + `structure` audit penalty) is directly on-trend, and re-confirming that the monorepo/nested wedge (decision #12 = `mono`) is still uncontested.

## 1. XDA Developers — "I gave Claude Code a 200-line CLAUDE.md, and it was the worst decision I made"
- **URL:** <https://www.xda-developers.com/gave-claude-code-200-line-claudemd-worst-decision-made/>
- **Signal:** Mainstream tech press (not just Reddit folk-rule) now names 200 lines as the practical failure threshold. Reports response quality drop, focus decrease, and hallucination increase as CLAUDE.md scales past ~200 lines.
- **Why it matters for us:** Our `long-file` rule (shipped today) is the first lint tool to encode this threshold as a checkable rule. Positioning: "the linter that actually knows the 200-line rule."

## 2. Anthropic official guidance surfaced in "CLAUDE.md Best Practices: The Complete 2026 Guide" (DEV Community)
- **URL:** <https://dev.to/nishilbhave/claudemd-best-practices-the-complete-2026-guide-435j>
- **Signal:** Aggregates Anthropic's own recommendation: CLAUDE.md should stay under 200 lines; practical high-signal limit is 80–120 lines. Attributes ~50 instruction-slots to Claude Code's own system prompt, leaving 100–150 usable slots for CLAUDE.md — hard cap reason, not aesthetic.
- **Why it matters for us:** Vendors the rule from an authoritative source. `audit`'s `structure` dimension now bleeds points past 200 lines — matches Anthropic's own advice mechanically.

## 3. GitHub Blog (still current) — "How to write a great agents.md: Lessons from over 2,500 repositories"
- **URL:** <https://github.blog/ai-and-ml/github-copilot/how-to-write-a-great-agents-md-lessons-from-over-2500-repositories/>
- **Signal:** Republished analysis still leading the "how to write AGENTS.md" search results in August. The six emphasized traits (persona, exact commands with flags, tech stack, file structure, workflows, boundaries, examples) map 1:1 onto our six `audit` dimensions.
- **Why it matters for us:** Decision #13 (map audit dimensions 1:1 to the GitHub rubric in the README) is looking more valuable each week — this article is now the de-facto canonical reference. ~1 hour of docs work, huge trust win. Recommend closing #13 = `yes` next loop.
