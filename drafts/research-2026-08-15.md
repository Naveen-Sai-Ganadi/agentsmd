# Research log — 2026-08-15

Fresh signals gathered while shipping `check --nested` (fourth and final vertical slice of monorepo mode; closes v0.1.1).

## Five fresh signals

1. **`github/copilot-cli#3051` — "Recursively discover AGENTS.md in subfolders, like VS Code's `chat.useNestedAgentsMdFiles`."** Open feature request against the Copilot CLI: currently the CLI only discovers AGENTS.md files along the CWD-to-git-root path, so sibling/deeper subfolder files are invisible when the CLI is started at the repo root. Direct echo of the primitive `agentsmd tree` + `--nested` already ships. Distinct from `#1655` (which asked for union semantics on the discovered set); this one is about *discovery* itself — a beat behind us. Source: <https://github.com/github/copilot-cli/issues/3051>.

2. **`anomalyco/opencode#7576` — auto-selection of nested AGENTS.md.** Still open. The issue thread now explicitly frames the problem as "the agent misses specific instructions in subdirectories" — a per-package correctness problem, exactly the framing our `check --nested` weakest-link gate solves. Second-consecutive-scan reference for us; the FR is not resolved upstream. Source: <https://github.com/anomalyco/opencode/issues/7576>.

3. **DEV — "CLAUDE.md Best Practices: The Complete 2026 Guide" (Nishil Bhave).** New long-form guide reinforcing the "lean root + focused per-package CLAUDE.md" pattern. Direct quote: "the lean briefing stays under ~200 lines because it pays context tax on every single turn." This is the *third* dated 2026 endorsement of the 200-line budget we already encode as the `long-file` rule — the rule keeps compounding. The guide's explicit "one 1,000-line megafile" anti-pattern is a perfect quote-back for the v0.1.1 launch reply. Source: <https://dev.to/nishilbhave/claudemd-best-practices-the-complete-2026-guide-435j>.

4. **`lowcode.agency` — "Claude Code for Monorepo Development 2026."** New monorepo playbook. Advocates per-package CLAUDE.md + affected-packages CI patterns. Notable because it takes the *CI-generation* angle: Claude Code generates GitHub Actions using an affected-packages pattern. That's the natural surface for `agentsmd check --nested` to plug into — the workflow it describes has no gate on nested-AGENTS.md quality. Positioning fit is clean. Source: <https://www.lowcode.agency/blog/claude-code-monorepo>.

5. **`giacomo/agents-lint` (closest active competitor) — still single-file.** Latest scan (8th consecutive) confirms the README continues to describe scanning "your AGENTS.md" (singular) — no nested/tree flag, no CI action, no per-package roll-up. The `seojoonkim/agentlinter` project also remains single-file in framing ("ESLint for AGENTS.md/CLAUDE.md," 100% local, no monorepo/nested language). Nested-CI lane is 100% uncontested for the eighth consecutive scan. Sources: <https://github.com/giacomo/agents-lint>, <https://github.com/seojoonkim/agentlinter>.

## Takeaway

Monorepo mode is now feature-complete on our side (`tree` → `lint --nested` → `audit --nested` → `check --nested`) while three of the biggest agent CLIs (Copilot CLI, opencode) still have open FRs asking for the *discovery* primitive that `agentsmd tree` shipped nearly two weeks ago. The two closest lint/audit competitors are still explicitly single-file. Best time to cut `v0.1.1` and start distributing — the story has never been cleaner: "one CI command; every AGENTS.md in the tree; weakest link fails the build."

**Positioning for the v0.1.1 launch:** "You have 12 AGENTS.md files. Copilot CLI can't see all of them (issue #3051). Nobody scores all of them. `agentsmd check --nested` fails your build the moment the weakest one drifts."
