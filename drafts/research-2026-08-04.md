# Research log — 2026-08-04

Focus: nested `AGENTS.md` discovery pain + active competitor moves on the
monorepo lane. This is the day the `tree` command shipped as the first
concrete step toward v0.1.1 monorepo mode (STATE.md decision #12 = `mono`).

## Signals

1. **agentsmd/agents.md Issue #53 — "When there are multiple agents.md files in a large monorepo, will it ignore the one at repo and use the nearest agents.md?"**
   <https://github.com/agentsmd/agents.md/issues/53>
   Direct user confusion on the canonical spec repo about nearest-wins vs.
   root discovery in monorepos.
   *Why it matters:* this is not a Reddit rant, it is a question on the
   spec repo itself. The spec deliberately leaves discovery up to the
   consumer, which is exactly the gap a lint/audit tool can close.

2. **anomalyco/opencode Issue #7576 — "[FEATURE]: Auto-selection of nested AGENTS.md based on file/directory context"**
   <https://github.com/anomalyco/opencode/issues/7576>
   A competing coding-agent CLI has an open FR to auto-pick the nearest
   `AGENTS.md` by file/dir context.
   *Why it matters:* confirms harnesses still do not uniformly implement
   nearest-wins. `agentsmd tree` (shipped today) already discovers the
   layout; `agentsmd lint --nested` / `check --nested` (next week) will
   enforce it independent of any single harness.

3. **codegateway.dev — "AGENTS.md for Codex CLI (2026): Lookup Order, Limits & Monorepo Templates"**
   <https://www.codegateway.dev/en/blog/agents-md-playbook-2026>
   Publishes Codex lookup order, size limits, and monorepo templates, and
   argues for frontmatter so harnesses can index nested `AGENTS.md`
   without loading bodies (progressive disclosure / token cost).
   *Why it matters:* the monorepo-playbook narrative is being shaped by a
   competitor's content marketing. The `audit` dimension mapping (already
   6 dims) should get a `frontmatter-present` sub-check in v0.1.1.

4. **morphllm.com — "AGENTS.md Spec (2026): Recommended Sections + AGENTS.md vs CLAUDE.md vs .cursorrules"**
   <https://www.morphllm.com/agents-md-guide>
   morphllm continues to publish spec + section guidance and format
   comparisons.
   *Why it matters:* an opinionated linter can encode morphllm's
   recommended sections as a rule pack; morphllm is now a persistent
   thought-leader in the space (also drove the 200-line pain).

5. **Medium (Cem Karaca) — "My CLAUDE.md Was Eating 42,000 Tokens Per Conversation — Here's How I Fixed It"**
   <https://medium.com/@cem.karaca/my-claude-md-was-eating-42-000-tokens-per-conversation-heres-how-i-fixed-it-85ffba809bd4>
   First-person story of a 1,207-line `CLAUDE.md` burning ~42k tokens per
   turn, tied to Anthropic's ~200-line guidance.
   *Why it matters:* the 200-line `long-file` rule shipped 2026-08-03 is
   directly on-point. In monorepo mode, `tree` gives us the primitive we
   need to sum sizes across nested files and warn on cumulative token
   burn, which is a rule no competitor ships yet.

## Takeaway

The monorepo/nested lane is still uncontested by every named competitor
(agnix, agentlinter, agent-audit, agents-lint, agentlint.app,
packmind/context-evaluator) — **5th consecutive scan confirming this.**
Two of today's signals (agents.md #53, opencode #7576) are the first
real evidence of *demand* for nearest-wins that isn't just our own
inference from the OpenAI 88-nested-files data point.

`tree` is the smallest possible bet on the wedge: it costs almost
nothing to ship, it dogfoods on a real monorepo the moment someone
installs it, and it defines the data model (`NestedConfig`,
`nearestConfig`) that `lint --nested`, `audit --nested`, and
`check --nested` will consume next.
