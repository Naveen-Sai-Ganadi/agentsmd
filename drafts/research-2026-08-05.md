# Research log — 2026-08-05

Focus of the scan: is anyone shipping a nested-`AGENTS.md` lint/audit
tool yet, and where are users asking for nearest-wins in their coding
agents this week?

## New signals

1. **`github/copilot-cli#1655` — "Flag for nested agents.md files along file hierarchy"**
   <https://github.com/github/copilot-cli/issues/1655>
   Open FR asking Copilot CLI to include *all* AGENTS.md along the
   hierarchy (union) instead of only root + nearest. Direct evidence
   for our decision #15 (`all` vs `nearest`) and a live end-user
   asking for exactly the union semantics `agentsmd lint --nested`
   now implements.

2. **`zed-industries/zed` discussion #53332 — "Zed Agent: Support nested AGENTS.md files in subdirectories"**
   <https://github.com/zed-industries/zed/discussions/53332>
   Zed users flagging that "most other agents have support for
   including AGENTS.md in subdirectories, automatically loaded when
   working on files within that subdirectory." Nearest-wins is now
   a *baseline expectation*, not a niche feature.

3. **`microsoft/vscode#271489` — "GitHub Copilot ignores nested AGENTS.md files but respects root-level ones"**
   <https://github.com/microsoft/vscode/issues/271489>
   Bug report: Copilot inside VS Code reads root AGENTS.md but
   ignores nested ones. Fresh 2026 user pain around the exact gap
   `tree` + `lint --nested` exist to make visible from CI.

4. **`openai/codex#12115` — "Dynamically loading nested AGENTS.md"**
   <https://github.com/openai/codex/issues/12115>
   Codex-side counterpart. OpenAI already "prioritizes deeper nested
   instructions in a cascading configuration pattern", and the main
   OpenAI repo carries 88 nested AGENTS.md files — the primary data
   point behind our v0.1.1 wedge.

5. **`code-yeongyu/pi-nested-agents-md` — "Nested AGENTS.md context injection for pi-mono coding-agent"**
   <https://github.com/code-yeongyu/pi-nested-agents-md>
   Ported from `omo` (oh-my-openagent). Walks up from any read file
   and injects nearby AGENTS.md into the tool result. **First shipped
   nested-AGENTS.md tool we've logged.** Important nuance: it is a
   *runtime injector for one specific agent* (pi-mono), not a
   linter/auditor / CI gate. The lint/audit/`check --nested` lane is
   therefore still uncontested; the discovery *primitive* now has one
   shipped implementation in the wild.

`codex#12115`) tell us the nested-`AGENTS.md` conversation moved

for the `--nested` family. Ship `audit --nested` next loop day and
