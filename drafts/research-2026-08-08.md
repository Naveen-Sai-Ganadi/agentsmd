# Research log — 2026-08-08

Focus: fresh (2–4 week window) signals for monorepo / nested `AGENTS.md`, per-package scoring, weakest-link CI gates, and any competitor that shipped per-file audit. Skipped everything already logged (`agnix`, `agentlint.app`, `agent-audit`, `code-yeongyu/pi-nested-agents-md`, morphllm data, codegateway playbook, etc.).

## 1. anthropics/claude-code#37344 — hierarchical `.claude` config discovery in monorepos
- <https://github.com/anthropics/claude-code/issues/37344>
- Open FR: Claude Code only reads root `.claude/`, misses per-package hooks/settings/MCP when editing subdirectory files.
- **Why it matters:** direct demand for the exact tree-walk `--nested` implements. Reinforces that per-package config is a first-class concern, not a doc quirk. Argues for `audit --nested` reporting per-file scores rather than a single global roll-up.

## 2. anthropics/claude-code#27901 — `claude --worktree` loses subdirectory context in monorepos
- <https://github.com/anthropics/claude-code/issues/27901>
- Complaint: worktree sessions attach to repo root and pick the wrong `CLAUDE.md`.
- **Why it matters:** confirms teams already keep divergent per-package instruction files and get bitten silently. An audit that surfaces per-package drift + a "weakest link" score is a natural fit.

## 3. anthropics/claude-code#20880 — opt-out for parent-`CLAUDE.md` auto-loading in subdirs
- <https://github.com/anthropics/claude-code/issues/20880>
- Users want to opt out of recursive parent-loading because irrelevant parent docs blow the context budget.
- **Why it matters:** this is the per-package scoping semantics conversation. Backs the mental model behind our rolled-up `overall` + `lowest` split — different packages carry different weight and need to be evaluated on their own terms.

## 4. Cursor community forum — "Cursor loads all rules from all folders in monorepo and blows past context limits"
- <https://forum.cursor.com/t/cursor-loads-all-rules-from-all-folders-in-monorepo-and-blows-past-context-limits/165337>
- July 2026 discussion; real dollar-cost pain from unscoped rule loading in monorepos.
- **Why it matters:** strengthens the weakest-link pitch: one bloated nested file taxes every session, so a per-package score that flags the outlier has direct ROI. Nice quote fodder for the launch draft.

## 5. `giacomo/agents-lint`
- <https://github.com/giacomo/agents-lint>
- Zero-dep CLI that verifies `AGENTS.md` / `CLAUDE.md` accuracy (stale paths, dead scripts, context rot) with a weekly GitHub workflow.
- **Why it matters:** closest active competitor. README does **not** mention nested/per-package traversal or a rolled-up score. **The `audit --nested` + weakest-link lane is still uncontested on the 7th consecutive scan.**

## Takeaway
- Monorepo / nested lane still 100% uncontested for `audit` — no shipped tool has per-package scoring + weakest-link roll-up.
- Three of five signals are from Claude Code itself (37344, 27901, 20880). That's the strongest concentration of a single tool's userbase asking for exactly the primitive we've built.
- Cursor forum thread is the first cost-oriented signal — worth reusing in the v0.1.1 launch angle ("one 1,200-line nested config = ~40k tokens *every session*").
